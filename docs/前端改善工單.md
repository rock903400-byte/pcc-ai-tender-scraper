### TICKET-A2　消除每次 rerun 的全量序列化

**優先級**：P0　**檔案**：`app.py`

**問題**
`json.dumps(st.session_state.tenders_all, ensure_ascii=False)` 被當成 `@st.cache_data` 的
cache key。Streamlit 每次互動都會重跑整個腳本，代表**使用者在快速搜尋框每打一個字，
就把全部標案序列化一次再算 hash**。數千筆時單次可達數十 MB，是目前介面最大的效能瓶頸。

**現況程式碼**（`app.py:1455-1459`）
```python
all_json = json.dumps(st.session_state.tenders_all, ensure_ascii=False)
matched_json = json.dumps(export_rows, ensure_ascii=False)
excel_bytes = cached_excel_bytes(all_json, matched_json)
csv_json = json.dumps(export_rows, ensure_ascii=False)
csv_bytes = cached_csv_bytes(csv_json)
```
同樣的模式也出現在 `app.py:1592-1593`（所有標案 CSV）與 `app.py:1682`（追蹤清單 CSV）。

**要求**
1. 新增輕量指紋函式，只雜湊識別欄位而非整份資料：
```python
def rows_fingerprint(rows: list) -> str:
    """以 pk（或標案案號）序列產生輕量指紋，用於 cache key。"""
    import hashlib
    h = hashlib.md5()
    h.update(str(len(rows)).encode())
    for r in rows:
        h.update((r.get("pk") or r.get("標案案號") or "").encode("utf-8"))
        h.update(b"|")
        h.update((r.get("決標方式") or "").encode("utf-8"))  # 補齊後會變動，需納入
        h.update(b"\n")
    return h.hexdigest()
```
2. 改寫 `cached_excel_bytes` / `cached_csv_bytes`，讓資料本體以
   `@st.cache_data` 忽略的參數傳入（底線開頭參數不參與 hash）：
```python
@st.cache_data(show_spinner=False)
def cached_excel_bytes(fingerprint: str, _all_tenders: list, _matched_tenders: list) -> bytes:
    return build_excel_bytes(_all_tenders, _matched_tenders)

@st.cache_data(show_spinner=False)
def cached_csv_bytes(fingerprint: str, _rows: list) -> bytes:
    return build_csv_bytes(_rows)
```
3. 三處呼叫端一併改用 `rows_fingerprint()`，並移除所有為了做 cache key 而寫的 `json.dumps`。

**注意**：`build_excel_bytes` / `build_csv_bytes` / `sanitize_rows` 的內容**不要動**，
只換 cache 包裝層。

**驗收標準**
- [ ] `grep -n "json.dumps" app.py` 的結果中，**不得**再有為了產生 cache key 而做的序列化
- [ ] 匯出的 Excel 有「精選_勞務最低標」「所有搜尋標案」兩個工作表，內容與修改前逐欄相同
- [ ] 匯出的 CSV 仍為 `utf-8-sig` 編碼、Excel 開啟不亂碼
- [ ] 公式注入防護仍生效：造一筆標案名稱為 `=1+1` 的資料，匯出後儲存格為 `'=1+1`
- [ ] 在「🏆 精選」快速搜尋框連續輸入 10 個字，頁面無明顯卡頓
- [ ] 補齊（trickle）後決標方式變動時，重新下載的檔案內容有跟著更新（指紋含決標方式）
