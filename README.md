# PCC AI & IT Service Tender Scraper (政府採購網 AI/資訊 勞務最低標爬蟲)

[![Python Version](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://www.python.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![GUI: ttkbootstrap](https://img.shields.io/badge/GUI-ttkbootstrap-info.svg)](https://ttkbootstrap.readthedocs.io/)

專門針對**台灣政府電子採購網 ([web.pcc.gov.tw](https://web.pcc.gov.tw))** 設計的自動化標案爬蟲與桌面 GUI 應用程式。

支援自動查詢最新發布之標案公告，並精準自動篩選：
- 🎯 **採購性質**：`勞務類`（亦可切換財物／工程／不限）
- 🎯 **決標方式**：`最低標` —— 先依招標方式推估，**再讀取公告上真正的「決標方式」欄位覆蓋**
  （主來源為公開資料鏡像 API，官網詳細頁備援），
  精確區分「最低標」與「參考最有利標／最有利標／評選」（詳見下方「決標方式為什麼會是『待確認』」）
- 🎯 **日期模式**：`等標期內`（現正招標中）或 `公告日期區間`
- 🏷️ **關鍵字**：`AI`、`人工智慧`、`資訊`、`網站`、`軟體`、`資安`、`人力資源` 等，
  **僅用於標記與快速篩選，不決定抓取範圍**

> **為什麼關鍵字不再決定抓取範圍？**
> 採購網的標案名稱查詢是子字串比對，名稱裡沒有資訊類字樣的案子就整筆抓不到——
> 例如「桃園醫院人力資源E指通計畫採購案」（勞務類 + 最低標）不含任何常見關鍵字。
> 因此本工具改為**掃描該條件下的全部標案**，再於結果中標記命中的關鍵字。

## 🖥️ 視覺化前端介面 (GUI) 功能

- 🎨 **現代化 Bootstrap 視覺設計**：卡片式佈局、直覺操作面板。
- 🔍 **全面掃描 + 關鍵字標記**：抓取範圍不受關鍵字影響；關鍵字取自 `config.py`，
  可於介面即時修改與重設，命中者顯示於「命中關鍵字」欄，未命中者以 `—` 標示。
  關鍵字只決定「精選」分頁的組成，不決定抓不抓得到。
- 📅 **日期模式切換**：`等標期內`（現正招標中；站方在此模式下會忽略日期區間，故「查詢天數」會停用）
  與 `公告日期區間`（查詢天數生效，未登入上限 186 天）。
- ⚡ **背景執行緒搜尋**：爬取過程 UI 不卡頓，具備即時進度條與執行紀錄。
- ⏹ **隨時可停止**：全面掃描動輒 120 頁要跑好幾分鐘，條件設錯時按同一顆按鈕（或 `Esc`）
  即可中斷，**中斷前抓到的標案照樣整理出來**，不會整批丟掉。
- 📢 **常駐警告列**：待確認筆數、詳細頁額度用盡、搜尋被中斷這類訊息會釘在表格上方，
  不會只躺在「執行紀錄」分頁裡被忽略；沒有警告時整條收起來不佔版面。
- 🖱️ **滑過看完整內容**：欄寬固定會截斷長標案名，滑鼠移到任一列即顯示完整名稱、機關、
  預算、決標方式與其可信度。
- ⌨️ **鍵盤操作**：`F5` 搜尋／停止、`Esc` 停止或清除篩選、`Ctrl+F` 跳到篩選框、
  `Ctrl+E` 匯出 Excel、關鍵字框按 `Enter` 直接開始。
- 🛡️ **深度校驗可開關**：開啟時只對「有機會入選且尚未確認」的標案查決標方式，
  主來源為公開資料鏡像（沒有官網那種額度限制），鏡像查無此案才退回官網詳細頁。
- ♻️ **確認結果自動累積**：每次搜尋確認到的決標方式都寫入 `output/award_cache.json`
  （key 為標案案號），下次搜尋自動套用、不重複查。**不需要任何手動操作**。
  快取條目滿 90 天自動失效並重新排隊——更正公告會改動決標方式，舊答案比「待確認」更危險。
- 🔄 **背景持續補齊**：開著這個開關，程式會**每 15 分鐘自己補一輪**（每輪 40 筆）決標方式，
  橘色列隨時間慢慢變少，使用者什麼都不必做（詳見下方說明）；
  搜尋進行中會自動讓路，不跟前景搶請求。
- 🟠 **未確認一目了然**：橘色列＝尚未確認的「公開取得 (待確認)」，灰色列＝已確認但不符篩選條件；
  精選分頁可勾「隱藏待確認」只看比較可信的列。
- 📄 **自動翻頁**：自動讀取搜尋結果的所有分頁（上限 120 頁／6,000 筆），超過上限會明確警告。
- 📊 **雙工作表分類檢視**：
  - **🏆 精選**：採購性質 ∩ 決標方式 ∩ **命中關鍵字**——因為全面掃描會撈回整批勞務標案
    （午餐、粉刷、校外教學…），精選需要關鍵字這層才有意義。勾選「包含未命中關鍵字」
    即可看回其餘符合條件者，分頁標題會同時顯示被折疊的筆數。
  - **📋 所有搜尋標案**：本次掃描到的完整標案清單（未命中關鍵字者永遠留在這裡）。
- ↕️ **型態感知排序**：點擊欄位標題切換升／降冪；金額依數值排序、日期依時序排序。
- 🔗 **一鍵直達官方頁面**：雙擊表格任意列或點擊「開啟選取標案網頁」。
- 💾 **報表匯出**：一鍵匯出 Excel (`.xlsx`) 或 CSV（兩者欄位與順序一致）；
  每次搜尋完成亦自動備份一份 Excel 至 `output/`。
- ⚙️ **記住上次的搜尋條件**：關鍵字、日期模式、查詢天數、採購性質、決標方式與各開關
  會存進 `output/ui_settings.json`，下次開啟自動還原，不必每天重打一次。

## 📁 專案架構

```text
pcc-ai-tender-scraper/
├── app.py                   # 桌面 GUI 應用程式入口
├── crawler.py               # 命令列 CLI 入口
├── pcc_core.py              # 共用核心：連線、分頁、解析、決標方式判定、報表輸出
├── pcc_mirror.py            # 決標方式的主來源：公開資料鏡像 API（無額度限制）
├── config.py                # 關鍵字與篩選規則設定檔
├── build_release.py         # 一鍵打包 EXE（秒開綠色版 + 瘦身單檔版）
├── requirements.txt         # 執行期相依套件
├── requirements-dev.txt     # 開發／打包／測試相依套件
├── tests/                   # 離線單元測試（以真實回應存檔為 fixture）
│   ├── conftest.py
│   ├── fixtures/            # 政府採購網回應存檔，測試不需連網
│   ├── test_pcc_core.py     # 核心邏輯（離線）
│   ├── test_pcc_mirror.py   # 鏡像來源與「鏡像優先、官網備援」流程（離線）
│   └── test_app_gui.py      # GUI 測試（本機需 PCC_GUI_TESTS=1；CI 以 xvfb 執行）
└── output/                  # 搜尋結果與報表輸出目錄（已 gitignore）
    ├── award_cache.json     # 已確認決標方式的永久快取（跨次執行累積，90 天有效）
    ├── pending_queue.json   # 待確認標案佇列（背景涓流校驗的取件來源）
    └── ui_settings.json     # GUI 上次使用的搜尋條件
```

`app.py` 與 `crawler.py` 皆為薄薄的入口層，所有爬取與解析邏輯集中在 `pcc_core.py`，
兩種介面行為必然一致。

### 方式 C：透過 CLI 終端機執行（適合自動排程）
```bash
# 預設執行（等標期內、現正招標中的勞務最低標）
python crawler.py

# 改以公告日期區間查詢最近 14 天
python crawler.py --date-mode 公告日期區間 --days 14

# 自訂標記關鍵字（不影響抓取範圍）
python crawler.py -k AI 人工智慧 網站 資訊安全

# 精選改為納入未命中關鍵字的標案（預設只收命中者）
python crawler.py --include-keyword-misses

# 略過決標方式深度校驗（快；未快取的標案決標方式僅為推估值）
python crawler.py --no-verify

# 調整批次校驗的筆數上限（預設 60；鏡像約 30–40 筆/分鐘，調高只是拉長本次執行時間）
python crawler.py --verify-limit 100

# 改查工程類的最有利標
python crawler.py --attr 工程 --award-way 最有利標/評選

# 只跑背景涓流校驗（不搜尋，只補決標方式）——掛進工作排程器每 15 分鐘跑一次
python crawler.py --verify-only

# 一次連跑 4 輪，每輪之間等 15 分鐘（不想用排程器時的替代作法）
python crawler.py --verify-only --rounds 4 --interval 900
```

> `--verify-only` 讀的是上一次搜尋留下的 `output/pending_queue.json`，
> 所以要先跑過一次搜尋產生佇列。佇列是空的時候它會直接結束，不會發出任何請求。

輸出檔案會寫入 `output/`，包含雙工作表 Excel（精選 + 所有標案）與一份精選 CSV；
GUI 匯出則跟著畫面上「精選」分頁目前顯示的內容走。
報表中的「決標方式來源」欄會標示該列的來源：**公開資料鏡像**或**官方詳細頁**（皆為公告上的實際值），
或僅為**依招標方式推估**。

## ⚠️ 決標方式為什麼會是「公開取得 (待確認)」

採購網的**搜尋結果頁沒有「決標方式」欄位**，只有「招標方式」。招標方式是「公開招標」時推估為
最低標大致可靠；但招標方式是**「公開取得報價單或企劃書」時完全看不出決標方式** —— 實測抽樣顯示
這類標案有相當比例其實是「參考最有利標精神」。因此這類列一律標成 `公開取得 (待確認)`，
**仍留在精選清單**（避免漏掉真正的最低標案），但以橘色標示提醒尚未確認。

官網要看這個欄位就得讀詳細頁，而站方對詳細頁採 **IP 層級的額度制**：

| 實測結果（2026-08） | 說明 |
| --- | --- |
| 約 **5 筆**就被擋 | 連續讀詳細頁約 5 筆後即回「驗證碼檢核」（撲克牌驗證碼）頁 |
| 拉長間隔沒用 | 間隔拉到 2 秒仍在第 6 筆被擋——是額度不是頻率 |
| 冷卻是分鐘級 | 被擋後等 30 秒不夠，實測靜置 15 分鐘也未必解除 |
| 換 session 沒用 | 清空 cookie 仍被擋，冷卻為 IP 層級 |

而待確認的量遠大於這個額度：全掃勞務類約有 1,098 筆待確認，等標期中位數 6 天，
換算下來**每天約有 157 筆新的待確認進來**——每天 96 輪也只補得到約 480 筆，
而且整段時間都在跟站方的防護硬碰硬。

**解法不是想辦法繞過那個額度，是換一個沒有額度的來源拿同一個欄位。**
g0v／openfun 的「標案瀏覽」鏡像（`pcc-api.openfun.app`）以政府公開資料重新發布同一批公告，
**含當日資料**，且 `detail` 內直接就有 `招標資料:決標方式`：

| 實測（2026-08-27） | 官網詳細頁 | 公開資料鏡像 |
| --- | --- | --- |
| 取得決標方式 | ✅ | ✅（隨機抽 15 筆「公開取得」案，命中 10/10，其餘為限流非缺欄位）|
| 一次請求涵蓋 | 1 筆 | `listbydate` 當日全部公告（該日 2,392 筆）|
| 節流 | 約 5 筆/輪、分鐘級 IP 冷卻 | 間隔 1.5 秒約 85% 成功，偶發 429 下一筆即恢復 |
| 實際吞吐 | 約 5 筆/輪 | 約 **30–40 筆/分鐘** |

所以本工具的順序是：**先問鏡像，鏡像查無此案才退回官網詳細頁**。
兩種失敗的處理也不同——鏡像回 429（暫時限流）時不會退回官網，免得白燒那 5 筆額度；
鏡像連續 5 筆查不到才判定它此刻不可靠，整輪改走官網。

實際機制：

1. **待確認佇列**：每次搜尋把「還沒確認、且有機會入選」的標案寫進
   `output/pending_queue.json`（含公告日期／機關／名稱，這是鏡像定位同一案的鑰匙），
   背景輪次直接從這裡取件，不必為了拿清單重跑整個全掃。
2. **背景涓流**：GUI 開著「背景持續補齊」即可；CLI 用 `--verify-only` 掛排程器。
   每 15 分鐘一輪、每輪 40 筆，一天約 96 輪 ≈ 3,800 筆，遠高於每天新增的 157 筆。
   間隔不再往下壓：鏡像是志工維運的免費服務，沒有理由把它當成自己的資料庫來刷。
3. **永久快取**：確認到的每一筆都寫進 `output/award_cache.json`（key 為標案案號，
   並記下是哪個來源確認的），下次先套快取，請求只花在還沒確認過的標案上。
   條目滿 90 天自動失效重新排隊，避免更正公告改了決標方式卻一直拿舊答案。
4. **講清楚剩下的**：沒確認到的維持推估值並標成橘色，執行紀錄會說明還剩幾筆；
   寫檔失敗（磁碟滿、資料夾唯讀）會明確報出來，不會靜默假裝存好了。

`config.py` 的 `USE_MIRROR_SOURCE = False` 可切回「只用官網詳細頁」的舊行為。
要立刻知道某一筆，雙擊該列（或按「🔗 開啟選取標案網頁」）自行查看最快。

### 為什麼不用官方開放資料一次抓完

官方確實有大量下載（`web.pcc.gov.tw/tps/tp/OpenData/showList`），但**救不了這個問題**，已實測確認：

- **招標資料 XML** 只有 6 個欄位（等標期、機關、案號、名稱、招標方式、採購性質），**沒有決標方式**。
- **決標資料 XML** 有 `TENDER_AWARD_WAY`，但那是**開標後**才產生的資料，投標前用不到。
- 兩者都**落後約兩個月**，且是 **GPA 子集**：單檔僅 195 筆，實際解析後**「公開取得」一筆都沒有**
  ——公開取得屬公告金額以下，本來就不在 GPA 範圍。

其他已排除的路：進階查詢表單（`indexTenderAdvanced`）只有 `tenderWay`（招標方式）沒有決標方式可供過濾。

> **更正（2026-08-27）**：先前記載「g0v 鏡像 `pcc.g0v.ronny.tw/api/*` 只回 SPA 空殼」——
> 實際上該服務只是**換了網域**。舊網域對所有路徑一律 301 到新網域的**根目錄**
> （`/api/listbydate?date=…` → `https://pcc-api.openfun.app/`，路徑不保留），
> 跟著轉址走就會落在首頁，看起來像是 API 死了。直接打新網域 `pcc-api.openfun.app`
> 的同名路徑，JSON 回得好好的——本工具的決標方式主來源就是它。

## 🧪 執行測試

測試以 `tests/fixtures/` 內的真實回應存檔為輸入，**完全離線、不會對政府採購網發出任何請求**：

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -v
```

另有一組會實際建立 Tk 視窗的 GUI 測試，需要桌面工作階段，在本機預設跳過；
以環境變數開啟：

```bash
PCC_GUI_TESTS=1 python -m pytest tests/ -v      # PowerShell: $env:PCC_GUI_TESTS=1
```

CI 會跑完整的兩份：核心測試在 Python 3.9 / 3.12 上執行，GUI 測試則以 `xvfb`
提供虛擬顯示器一併納入把關（先前 GUI 測試只能在本機手動跑，等於 CI 沒守到）。

- 決標方式的主來源 `pcc-api.openfun.app` 是**志工維運的免費服務**，

  並把結果永久快取避免重複查詢；請勿自行調低 `pcc_mirror.MIRROR_DELAY_RANGE`。
- 詳細頁的驗證碼防護是 IP 層級的冷卻，被擋下後換連線階段也無效；此時剩餘標案會維持推估值，
  可稍後再試或改用 `--no-verify`。
- `config.py` 的關鍵字只用於標記命中，調整清單不會增加對伺服器的請求數。
